# Slider AI 정리

## 1. 파일 구성

| 파일 | 역할 |
|---|---|
| `Game.java` | 콘솔 게임. AI 차례에 `Calculate`를 호출하고, 돌려받은 `w/a/s/d` 목록을 `Move.tryMove`로 실행 |
| `Learning/Calculate.java` | `Game`과 AI를 잇는 어댑터. 보드 배열을 비트보드로 바꾸고 결과를 이동 목록으로 돌려줌 |
| `Learning/BitBoard.java` | 비트보드 표현과 이동 생성 (걷기 + 미끄러지기) |
| `Learning/SliderAI.java` | 탐색과 평가 함수 |
| `test/.../SliderAITest.java` | 이동 규칙 일치, 즉시 승리, 위협 차단, 무작위 상대 대국 테스트 |

`Calculate` 사용법:

```java
Calculate cal = new Calculate(board, playerLoc, aiLoc);        // 기본 1.5초
Calculate cal = new Calculate(board, playerLoc, aiLoc, 500);   // 시간 지정(ms)
List<String> moves = cal.findsolve();   // 예: [w, d] — 걷기 후 마지막이 미끄러지기. 둘 수 없으면 빈 목록
cal.getScore();          // AI 기준 평가 점수 (양수면 AI 유리)
cal.getDepth();          // 끝까지 탐색한 깊이 (ply)
cal.getPlayerWinRate();  // 점수를 0~1로 바꾼 대략적인 플레이어 승률
```

## 2. 보드 표현 (`BitBoard`)

- 칸 번호 = `row * 7 + col`. 타일이 있는 칸은 `long`의 비트가 1입니다.
- **이동 하나 = 한 턴 전체**: 걸어갈 수 있는 타일 중 하나(`from`)에서 방향(`dir`)으로 미끄러져 `dest`에 멈추는 것입니다.
  - `int` 하나에 `from | dir << 6 | dest << 8`로 담습니다.
  - 결과 국면은 `from`과 `dest`로 정해지므로 중복이 없습니다. 한 국면의 이동은 최대 44개 정도입니다.
- `reach`: 상대 칸을 피해 걸어갈 수 있는 타일 집합 (BFS).
- `toSymbols`: 고른 이동을 `Game`이 실행할 `w/a/s/d` 경로로 바꿉니다 (BFS 최단 걷기 경로 + 미끄러지기 1회).
- 기본 보드에서는 "움직일 수 없는 상태"가 생기지 않습니다. 7x7 격자는 칸 하나(상대)로 끊기지 않기 때문입니다. 그래도 탐색에서는 차례 넘기기로 처리합니다.

## 3. 탐색 (`SliderAI`)

### 기본 구조
- **알고리즘**: 반복 심화 negamax + 알파베타 가지치기
- **트랜스포지션 테이블**: 2^19칸, 약 11MB
- **수 정렬**: TT 최선수 → 킬러 수 2개 → 히스토리 점수 + 도착 칸 위치 점수
- **루트 창**: 최선수와 `MARGIN`(40점) 이내인 수들은 정확한 점수가 나오도록 창을 넓혀서 탐색합니다.
- **시간 관리**: 깊이 1은 항상 끝까지 탐색하고, 그 이후는 시간이 끝나면 중단합니다. 마지막으로 **끝낸** 깊이의 결과만 씁니다.

### 2단계 수 선택
이 게임은 서로 위협을 막기만 하면 끝나지 않습니다. 그래서 순수 minimax는 지지는 않지만 이기려 하지도 않습니다 (4장 참고).
1. **안전 확인** (시간의 50%): 정확한 minimax로 모든 수를 평가하고, 최선과 `MARGIN` 이내인 수만 남깁니다. 확정 승패가 나오면 바로 그 수를 둡니다.
2. **공격 계획** (나머지 50%): 남은 수들만 다시 탐색합니다.
   - `PLAN_PLY`(5 ply)부터는 "상대는 바로 이기거나 내 직접적인 위협을 막을 때만 움직이고, 아니면 수를 쉰다"고 가정합니다.
   - 상대의 첫 두 응수(1·3 ply)는 모두 봅니다.
   - 이 가정으로 찾은 승리는 `PLAN_WIN`(5000 − ply)으로, 확정 승리 `WIN`(100000 − ply)과 구분합니다.
3. **최종 선택**: 2단계 점수 + 함정 보너스(`TRAP_WEIGHT` 60 × 상대 응수 중 내가 바로 이기게 되는 비율)가 가장 높은 수를 고릅니다.

TT 키에는 탐색 방식(정확 / 낙관 / 낙관까지 남은 ply)을 같이 넣어서, 서로 다른 의미의 점수가 섞이지 않게 했습니다.

## 4. 평가 함수

말단에서 "둘 차례인 쪽" 기준으로 계산합니다. 둘 차례인 쪽이 바로 이길 수 있으면 평가 전에 승리로 처리합니다.

| 항목 | 정의 | 점수 |
|---|---|---|
| 상대의 즉시 위협 | 상대가 다음 차례에 바로 이기는 수의 개수 | 1개 −150, 2개 이상 −(400 + 50×개수) |
| 직선별 승리 거리 | 골로 들어가는 4방향마다 `받침 비용 + 진입 비용 + 1` | 2수 150, 3수 70, 4수 30, 5수 12 (내 합 − 상대 합) |
| 이동 가능 수 | 미끄러질 수 있는 수의 개수 차이 | ×1 |
| 걸을 수 있는 타일 | 개수 차이 | ×2 |
| 위치 | 중앙에 가까울수록 높은 표 (0~7) | 차이 |

- **받침 비용**: 골 바로 옆 칸에 타일을 세우는 데 필요한 타일 이동 수의 어림값입니다.
  - 이미 타일이 있으면 0입니다.
  - 아니면 타일이나 벽에서 빈 칸을 따라 잰 거리입니다. 타일은 타일/벽 앞에서만 멈추기 때문입니다.
- **진입 비용**: 그 직선 위의 첫 타일을 이미 밟을 수 있으면 0, 다음 수에 직선 위로 올라갈 수 있으면 1, 그 외는 2입니다.

## 5. 성능 측정 결과

**측정 조건**
- 상대 종류:
  - **무작위**: 가능한 수 중 무작위
  - **초보**: 이길 수 있으면 이기고, 아니면 AI에게 즉시 승리를 주지 않는 수 중 무작위
  - **순수 minimax**: 2단계 없이 정확한 탐색만 하는 AI
- 무작위/초보전은 상대가 먼저 둡니다. AI끼리는 선후를 번갈아 하고 첫 수는 무작위입니다.
- 60~80라운드(양쪽 한 수씩) 안에 끝나지 않으면 무승부로 셉니다.

| 상대 | 시간/수 | 결과 | 평균 승리 라운드 |
|---|---|---|---|
| 무작위 | 100ms | 20전 20승 | 30 |
| 초보 | 100ms | 19승 1무 0패 | 26 |
| 초보 | 1.5초 (게임 기본값) | 8전 8승 | 약 22 |
| 순수 minimax (같은 평가 함수) | 100ms | 20전 20무 | — |
| 순수 minimax (계획 점수 없는 평가 함수) | 100ms | 20전 20무 | — |

시간 제한 탐색이라 결과는 실행마다 조금씩 달라집니다.

### 개발 과정에서 확인한 것
| 시도 | 결과 | 원인 / 대응 |
|---|---|---|
| 순수 minimax + 단순 평가 | 무작위 상대로도 20판 중 4~10승, 나머지 무승부 | 상대가 완벽하게 막는다고 가정해서 구조를 쌓지 않음 |
| 상대가 움직이지 않는 상황 (자기 수만으로 이기기까지의 거리) | 측정한 모든 국면에서 5수 이상 | 이기려면 골 근처에 타일 구조를 여러 수에 걸쳐 쌓아야 함 → "승리 거리" 평가 도입 |
| 낙관 탐색만 사용 (3 ply부터) | 5 ply 버전에 3승 17패 | 상대의 두 번째 응수를 안 봐서 이중 위협을 놓침 |
| 낙관 탐색만 사용 (5 ply부터) | 순수 minimax에 0승 8무 12패 | 상대의 장기 반격을 못 봄 → 2단계 방식(안전 확인 후 계획 선택)으로 해결, 0패 |

## 6. 함께 고친 버그

- **`Move.java` 위아래 이동**: 목표 행을 `row + dy` 대신 `dy`로 계산하고 있었습니다. 위로(`w`) 움직이면 `ArrayIndexOutOfBoundsException`이 났습니다.
- **기존 AI 클래스 삭제**: `backtrackingAI`, `backtrackingPlayer`, `Minimax`, `LocationSurrounding`, `VirtualBoard`는 가상 이동에서 행/열 방향이 뒤바뀌어 있었고, 보드 배열을 공유해 상태가 섞였습니다. 삭제했고 git 기록에 남아 있습니다.

## 7. 알려진 한계

- **무승부 규칙 없음**: 서로 막기만 하면 게임이 끝나지 않습니다.
- **승률 표시**: `1/(1+e^(점수/200))`로 바꾼 값이라 실제 승률과 맞춰져 있지 않습니다.
- **실행마다 다른 수**: 시간 제한 탐색이라 같은 국면에서도 다른 수를 둘 수 있습니다.
- **`Game` 구조**:
  - `playerTurn`과 `EnemyTurn`이 서로를 재귀 호출합니다.
  - 매 턴 `Scanner`를 새로 만듭니다 (입력을 파이프로 넣으면 줄이 사라질 수 있음).
  - 플레이어가 이기면 "You win"이 두 번 출력됩니다.

## 8. 다음 계획: 수 점수화 → 자가대전 튜닝

### 8.1 점수 단위
| 층 | 값 | 용도 |
|---|---|---|
| 확정 결과 | ±100000 − 걸리는 수 | 전부 |
| 계획 점수 | ±5000 − 걸리는 수 | 수 선택에만 (표시·학습에는 안 씀) |
| 휴리스틱 | 대략 ±1000 | 전부 |

### 8.2 수 등급 (손실 = 최선수 점수 − 이 수 점수, 정확한 minimax 기준)
| 등급 | 조건 |
|---|---|
| 승리수 | 확정 승리 유지 |
| 최선 | 손실 0 |
| 좋음 | 손실 < 40 |
| 부정확 | 손실 < 150 |
| 실수 | 손실 < 400 |
| 대실수 | 확정 패배로 바뀌거나 상대에게 즉시 승리 허용 |

### 8.3 진행 순서
1. **점수 내역 기록**: `Result`에 특징별 점수, 후보 수 상위 3개, 선택 이유(안전 / 계획 / 함정 점수)를 추가하고 게임 화면에 옵션으로 보여줍니다.
2. **무승부 규칙과 등급 판정기**: 수 제한 + 같은 국면 3회 반복을 무승부로 처리하고, 수 등급 판정기를 만듭니다.
3. **자가대전 데이터 생성기**: AI끼리 대국하며 국면, 특징 값, 탐색 점수, 최종 결과를 JSONL로 기록합니다 (Java, 코랩에서도 실행).
4. **코랩 노트북**:
   - (점수, 결과)로 승/무/패 확률을 보정합니다.
   - Texel 방식(sigmoid(평가)와 결과의 오차 최소화)으로 가중치를 튜닝하고 JSON으로 출력합니다.
5. **벤치마크와 교체**: 5장 표와 퍼즐 세트("N수 안에 이김", "반드시 막아야 함")를 돌립니다. 이전 버전 상대로 패배가 늘지 않고 초보 상대 승리가 빨라지면 기본값을 교체합니다.

추가로 실험해볼 평가 항목: 이중 위협 잠재력, 받침 칸이 누구의 직선과 짝인지, 템포 보정, 상대 경로 차단.
