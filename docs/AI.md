# Slider AI 정리

규칙은 **말 2개씩** (README 참고): 한 턴에 말 하나, 어느 말이든 골에 멈추면 승리, 다른 말이 있는 칸은 못 지나감,
둘 수 있는 수가 없으면 차례 넘김, 같은 국면 3번째 반복은 무승부.

## 1. 파일 구성

`Calculate` 사용법:

```java
// 말은 {row, col} 목록
Calculate cal = new Calculate(board, playerPieces, aiPieces);        // 기본 1.5초
Calculate cal = new Calculate(board, playerPieces, aiPieces, 500);   // 시간 지정(ms)
cal.withGameHistory(positions);         // 실제 게임에서 나온 국면 횟수 (3회 반복 판정용, 선택)
List<String> moves = cal.findsolve();   // 예: [w, d] — 걷기 후 마지막이 미끄러지기. 둘 수 없으면 빈 목록(차례 넘김)
cal.getPieceLocation();  // 이번 턴에 움직이는 AI 말의 현재 {row, col}. 차례를 넘기면 null
cal.getScore();          // AI 기준 평가 점수 (양수면 AI 유리)
cal.getDepth();          // 끝까지 탐색한 깊이 (ply)
cal.getPlayerWinRate();  // 점수를 0~1로 바꾼 대략적인 플레이어 승률
Calculate.movablePieces(board, mine, theirs);  // 말별로 이번 턴에 둘 수 있는 수가 있는지
```

말이 1개씩인 이전 생성자 `new Calculate(board, playerLoc, aiLoc)`도 그대로 쓸 수 있습니다.

## 2. 보드 표현 (`BitBoard`)

- 칸 번호 = `row * 7 + col`. 타일이 있는 칸은 `long`의 비트가 1입니다.
- **말도 `long` 비트마스크**입니다 (한 편에 비트 2개). 말이 서 있는 칸은 항상 타일입니다. 같은 편 말끼리는 순서가 없어서, 말을 바꿔 놓은 같은 국면이 자동으로 하나로 합쳐집니다.
- **이동 하나 = 한 턴 전체**: 말 하나(`src`)가 걸어갈 수 있는 타일 중 하나(`from`)에서 방향(`dir`)으로 미끄러져 `dest`에 멈추는 것입니다.
  - `int` 하나에 `from | dir << 6 | dest << 8 | src << 14`로 담습니다.
  - 결과 국면은 (`src`, `from`, `dest`)로 정해지므로 중복이 없습니다. 최대 `MAX_MOVES`(392)개까지 담을 수 있게 잡았습니다.
- `reach`: 다른 말(상대 말, 내 다른 말)이 있는 칸을 피해 걸어갈 수 있는 타일 집합 (BFS). 말마다 따로 구합니다.
- `generate`: 두 말의 이동을 모두 모읍니다. 하나도 없으면 0 (차례 넘김).
- `toSymbols`: 고른 이동을 `Game`이 실행할 `w/a/s/d` 경로로 바꿉니다 (움직이는 말의 BFS 최단 걷기 경로 + 미끄러지기 1회).
- 말 2개씩일 때는 갇힘이 실제로 일어납니다. 예를 들어 귀퉁이 말의 두 이웃 칸이 모두 다른 말이면 걷지도 미끄러지지도 못합니다. 탐색은 이 경우 차례를 넘깁니다.

## 3. 탐색 (`SliderAI`)

### 기본 구조
- **알고리즘**: 반복 심화 negamax + 알파베타 가지치기
- **트랜스포지션 테이블**: 2^19칸, 약 19MB (국면 = 타일 + 내 말 + 상대 말 + 탐색 방식)
- **수 정렬**: TT 최선수 → 킬러 수 2개 → 히스토리 점수 + 도착 칸 위치 점수
- **루트 창**: 최선수와 `MARGIN`(40점) 이내인 수들은 정확한 점수가 나오도록 창을 넓혀서 탐색합니다.
- **시간 관리**: 깊이 1은 항상 끝까지 탐색하고, 그 이후는 시간이 끝나면 중단합니다. 마지막으로 **끝낸** 깊이의 결과만 씁니다.

### 차례 넘기기와 3회 반복
- 둘 수 있는 수가 없으면 차례를 넘기고 탐색을 이어갑니다. 둘 다 못 움직이면 같은 국면이 반복되어 무승부로 끝납니다.
- **반복 = 무승부(0점)**: 탐색 경로에서 같은 국면이 한 번이라도 다시 나오면 순환으로 보고 무승부로 처리합니다. 실제 게임에서 이미 2번 나온 국면(`setGameHistory`)에 닿으면 3번째라서 무승부입니다.
- 국면 해시는 `positionHash(tiles, 둘 차례인 쪽 말, 반대편 말)`이라 누구 차례인지도 구분합니다.

### 2단계 수 선택
이 게임은 서로 위협을 막기만 하면 끝나지 않습니다. 그래서 순수 minimax는 지지는 않지만 이기려 하지도 않습니다 (5장 참고).
1. **안전 확인** (시간의 50%): 정확한 minimax로 모든 수를 평가하고, 최선과 `MARGIN` 이내인 수만 남깁니다. 확정 승패가 나오면 바로 그 수를 둡니다.
2. **공격 계획** (나머지 50%): 남은 수들만 다시 탐색합니다.
   - `PLAN_PLY`(5 ply)부터는 "상대는 바로 이기거나 내 직접적인 위협을 막을 때만 움직이고, 아니면 수를 쉰다"고 가정합니다.
   - 상대의 첫 두 응수(1·3 ply)는 모두 봅니다.
   - 이 가정으로 찾은 승리는 `PLAN_WIN`(5000 − ply)으로, 확정 승리 `WIN`(100000 − ply)과 구분합니다.
3. **최종 선택**: 2단계 점수 + 함정 보너스(`TRAP_WEIGHT` 60 × 상대 응수 중 내가 바로 이기게 되는 비율)가 가장 높은 수를 고릅니다.

TT 키에는 탐색 방식(정확 / 낙관 / 낙관까지 남은 ply)을 같이 넣어서, 서로 다른 의미의 점수가 섞이지 않게 했습니다.

## 4. 평가 함수

말단에서 "둘 차례인 쪽" 기준으로 계산합니다. 둘 차례인 쪽이 바로 이길 수 있으면 평가 전에 승리로 처리합니다.
**평가 점수 = 가중치 · 특징**의 선형식이라, 코랩에서 가중치만 바꿔 튜닝할 수 있습니다 (`EvalWeights`).
말이 2개라서 이동 수와 걸을 수 있는 타일은 두 말의 합이고, 승리 거리는 가장 가까운 말이 기준입니다.

| 가중치 이름 | 특징 | 기본값 |
|---|---|---|
| `threat1` | 상대가 바로 이기는 수가 정확히 1개면 1 | −150 |
| `threat2` | 그 수가 2개 이상이면 1 | −400 |
| `threat2PerThreat` | 그 경우의 수의 개수 | −50 |
| `mobility` | (내 이동 가능 수) − (상대의 것) | 1 |
| `reach` | (내 말들이 걸을 수 있는 타일 수) − (상대의 것) | 2 |
| `plan2` ~ `plan5` | 골로 들어가는 4방향 직선 중 이기기까지 남은 수(어림)가 2~5수인 직선 개수의 (나 − 상대) | 150, 70, 30, 12 |
| `position` | 중앙에 가까울수록 높은 표(0~7)의 말 합 차이 | 1 |
| `tempo` | 항상 1 (둘 차례인 쪽의 이점) | 0 |

기본값은 손으로 정한 값이고, 말 1개 버전의 상수와 같습니다 (`tempo`만 새로 추가, 0).

- **받침 비용**: 골 바로 옆 칸에 타일을 세우는 데 필요한 타일 이동 수의 어림값입니다.
  - 이미 타일이 있으면 0입니다.
  - 아니면 타일이나 벽에서 빈 칸을 따라 잰 거리입니다. 타일은 타일/벽 앞에서만 멈추기 때문입니다.
- **진입 비용**: 그 직선 위의 첫 타일을 이미 밟을 수 있으면 0, 다음 수에 직선 위로 올라갈 수 있으면 1, 그 외는 2입니다.
- 직선별 승리 거리 = `받침 비용 + 진입 비용 + 1`.

## 5. 성능 측정 결과

### 2v2 (현재 규칙)

- 무작위 상대 (테스트 `beatsRandomPlayer`): 60ms/수, 10판에서 AI가 8승 이상 (보통 전승), 무작위 쪽 승리 0.
- 자가대전: 기본 가중치끼리, 30ms/수, 시작 4수는 무작위, 이후 5% 확률로 무작위 수, 150 ply 안에 안 끝나면 무승부.

  | 판 수 | 먼저 둔 쪽 승 | 무승부 | 나중 둔 쪽 승 |
  |---|---|---|---|
  | 120 | 35 | 33 | 52 |

  나중에 둔 쪽이 더 많이 이겼지만 결판 난 87판 기준으로 통계적으로 확실하다고 하기는 어렵습니다.
- 가중치 튜닝 시도 (코랩 방식 요약, 9장): 120판 자가대전 데이터(국면 11,687개 중 확정 승패 제외 11,187개)에서
  평가 점수와 판 결과의 상관계수는 0.018, 탐색 점수와 판 결과는 0.087로 약했습니다.
  승패에 맞춰 튜닝한 가중치는 기본값에 3승 27무 10패 (40판, 점수 0.41),
  탐색 점수에 맞춰 튜닝한 가중치는 17승 26무 17패 (60판, 점수 0.50)였습니다.
  **이 규모에서는 튜닝으로 강해진다는 증거를 얻지 못했습니다.**
- 평가 점수의 표준편차(91)가 탐색 점수(50)의 거의 두 배라서, 정적 평가가 탐색 결과보다 과하게 확신하는 경향은 있습니다.

### 1v1 (이전 규칙, 참고)

**측정 조건**
- 상대 종류:
  - **무작위**: 가능한 수 중 무작위
  - **초보**: 이길 수 있으면 이기고, 아니면 AI에게 즉시 승리를 주지 않는 수 중 무작위
  - **순수 minimax**: 2단계 없이 정확한 탐색만 하는 AI
- 무작위/초보전은 상대가 먼저 둡니다. AI끼리는 선후를 번갈아 하고 첫 수는 무작위입니다.
- 60~80라운드(양쪽 한 수씩) 안에 끝나지 않으면 무승부로 셉니다.

| 상대 | 시간/수 | 결과 | 평균 승리 라운드 |
|---|---|---|---|
| 무작위 | 100ms | 20전 20승 | 30 |
| 초보 | 100ms | 19승 1무 0패 | 26 |
| 초보 | 1.5초 (게임 기본값) | 8전 8승 | 약 22 |
| 순수 minimax (같은 평가 함수) | 100ms | 20전 20무 | — |
| 순수 minimax (계획 점수 없는 평가 함수) | 100ms | 20전 20무 | — |

시간 제한 탐색이라 결과는 실행마다 조금씩 달라집니다.

### 개발 과정에서 확인한 것 (1v1)
| 시도 | 결과 | 원인 / 대응 |
|---|---|---|
| 순수 minimax + 단순 평가 | 무작위 상대로도 20판 중 4~10승, 나머지 무승부 | 상대가 완벽하게 막는다고 가정해서 구조를 쌓지 않음 |

## 6. 함께 고친 버그

- **`Move.java` 위아래 이동**: 목표 행을 `row + dy` 대신 `dy`로 계산하고 있었습니다. 위로(`w`) 움직이면 `ArrayIndexOutOfBoundsException`이 났습니다.
- **기존 AI 클래스 삭제**: `backtrackingAI`, `backtrackingPlayer`, `Minimax`, `LocationSurrounding`, `VirtualBoard`는 가상 이동에서 행/열 방향이 뒤바뀌어 있었고, 보드 배열을 공유해 상태가 섞였습니다. 삭제했고 git 기록에 남아 있습니다.
- **`Game` 구조 (2v2 개편과 함께)**: `playerTurn`/`EnemyTurn`의 상호 재귀 호출, 매 턴 `Scanner`를 새로 만들던 것, 플레이어 승리 시 "You win"이 두 번 출력되던 것을 고쳤습니다. 하나의 루프와 하나의 `Scanner`를 씁니다.

## 7. 알려진 한계

- **반복 판정은 탐색에서 근사입니다**: 경로에서 한 번만 반복돼도 무승부로 보고, TT에는 이력에 의존하는 무승부 점수가 섞일 수 있습니다. 실제 게임의 3회 반복 판정(`Game`)은 정확합니다.
- **승률 표시**: `1/(1+e^(점수/200))`로 바꾼 값이라 실제 승률과 맞춰져 있지 않습니다. 5장의 상관계수를 보면 점수가 승패를 잘 설명하지 못합니다.
- **실행마다 다른 수**: 시간 제한 탐색이라 같은 국면에서도 다른 수를 둘 수 있습니다. 같은 가중치끼리 맞붙여도 결과가 0.5 근처에서 흔들립니다.
- **무승부가 많음**: 자가대전의 약 28%, 가중치 비교 대국(무작위 시작 6수, 50ms 이하)에서는 절반 넘게 무승부였습니다. 결판이 난 판이 적어서 가중치 비교에 판 수가 많이 필요합니다.
- **갇힘 처리**: 콘솔에서 사람이 걷다가 더 못 움직이게 되면 `r`로 그 턴을 다시 해야 합니다.

| 실수 | 손실 < 400 |
| 대실수 | 확정 패배로 바뀌거나 상대에게 즉시 승리 허용 |

### 8.3 진행 순서
1. **점수 내역 기록**: (미구현) `Result`에 특징별 점수, 후보 수 상위 3개, 선택 이유(안전 / 계획 / 함정 점수)를 추가하고 게임 화면에 옵션으로 보여줍니다.
2. **무승부 규칙**: 완료. 같은 국면 3회 반복 (`Game`과 탐색 모두). 자가대전/대국 도구에는 150 ply 상한이 따로 있습니다. 수 등급 판정기는 미구현입니다.
3. **자가대전 데이터 생성기**: 완료 (`SelfPlay`). 국면, 특징 값, 탐색 점수, 최종 결과를 JSONL로 기록합니다.
4. **코랩 노트북**: 완료 (`colab/slider_2v2_training.ipynb`). 눈금을 보정한 뒤 Texel 방식으로 가중치를 튜닝하고 JSON으로 출력합니다.
5. **벤치마크와 교체**: 대국 비교(`Match`)는 완료. 퍼즐 세트("N수 안에 이김", "반드시 막아야 함")는 미구현입니다. 지금은 기본값을 바꿀 만한 근거가 없어서 기본값을 그대로 둡니다.

추가로 실험해볼 평가 항목: 이중 위협 잠재력(두 말이 서로 다른 직선을 노리는지), 받침 칸이 누구의 직선과 짝인지, 템포 보정, 상대 경로 차단, 같은 편 두 말의 협력(한 말이 다른 말의 받침 타일이 되는 구도).

### 8.4 정해야 할 것

- 목표: 최대한 강한 AI인지, 난이도를 조절할 수 있는 AI인지

## 9. 코랩 학습 (`colab/slider_2v2_training.ipynb`)

흐름: 자가대전 → 학습 → 대국 확인을 `ROUNDS`번 반복합니다.

1. **자가대전** (`SelfPlay`): 현재 가중치의 AI끼리 두고, AI가 직접 고른 수 앞의 국면마다 한 줄씩 기록합니다.
   `{"game", "ply", "side", "features"[11], "score", "outcome"}`. `outcome`은 둘 차례였던 쪽 기준 승 1 / 무 0.5 / 패 0입니다.
   처음 몇 수를 무작위로 두고 이후에도 일정 확률로 무작위 수를 둬서 국면을 다양하게 합니다.
2. **학습** (Texel): `P(승) = sigmoid(점수 / K)`로 보고 결과와의 제곱오차를 L-BFGS로 최소화합니다.
   - 눈금 `K`를 현재 가중치를 고정한 채 **먼저** 보정합니다. 건너뛰면 "점수가 과하게 크다"는 정보를 가중치 전체가 줄어드는 것으로 떠안아서 탐색 상수(`MARGIN` 등)와 척도가 어긋납니다.
   - 기본 가중치에서 멀어지지 않게 정규화하고, 판 단위로 80/20으로 나눠 정규화 세기를 검증 오차로 고릅니다.
   - 탐색이 승패를 확정한 국면(|점수| ≥ 50000)은 뺍니다.
   - 신호 진단: 평가점수-승패 상관, `K`가 탐색 범위 끝에 붙는지. 신호가 없으면 그 라운드의 학습은 건너뜁니다.
3. **대국 확인** (`Match`): 새 가중치 vs 현재 가중치, 시작 국면마다 쪽을 바꿔 두 판씩. 점수가 `ACCEPT_SCORE`(0.55) 이상일 때만 채택합니다.
   같은 가중치끼리도 0.5 근처에서 흔들리므로 0.5 초과만으로는 채택하지 않고, 학습 결과가 현재 가중치와 같으면 대국을 건너뜁니다.

검증하면서 고친 것:
- L-BFGS가 시작점의 기울기가 너무 작아서(1e-5 수준) 한 걸음도 안 가고 "수렴"으로 멈추던 문제. 변수를 눈금 단위로 다시 매기고 종료 기준을 엄격하게 했습니다.
- 눈금 `K`를 고정 200으로 두면 튜닝 결과가 전반적으로 쪼그라들고(예: `plan2`가 음수), 그 가중치가 기본값에 크게 졌습니다.
- 신호가 약한데도 학습하면 가중치가 ±3000으로 폭주해서, 신호가 없으면 학습을 건너뜁니다.

로컬 검증: 합성 데이터(정답 가중치를 아는)로 정답 복원과 정규화 동작을 확인했고, 노트북 코드 셀을 순서대로 실행해
컴파일 → 자가대전 → 학습 → 대국 → 저장까지 끝까지 도는 것을 소규모와 중간 규모(120판)로 확인했습니다.
